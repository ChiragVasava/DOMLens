# DOMLens — Technical Architecture & Resume Audit

This document provides a comprehensive, architectural, and brutally honest technical audit of the entire **DOMLens** workspace.

---

### 1. Programming Languages

- **JavaScript (ES2023 / Modern ES Modules)**: Used across the entire project (100% of runtime logic, content scripts, background worker, popup, DOM extractors, code generators, and test harnesses). Employs modern syntax including optional chaining, nullish coalescing, async/await, `AbortController`, `ReadableStream`, and ES module dynamic imports.
- **HTML5**: Used for extension popup UI (`popup/popup.html`), test playgrounds (`scratch/test_page.html`), sandboxed iframe preview compilation (`srcdoc`), and DOM extraction fixtures.
- **CSS3**: Custom CSS custom property token system, modern layouts (Flexbox, Grid), CSS glassmorphism (`backdrop-filter`), CSS transforms, and CSS animations.
- **SVG**: Vector graphics authoring in `assets/logo.svg` and programmatic SVG AST manipulation in code generators (converting SVG attributes to React camelCase).
- **JSX**: Hand-authored test components and programmatically synthesized React components generated by `component_generator.js`.
- **Node.js (Runtime)**: Used for executing standalone automation scripts and zero-dependency test suites.

*(Languages NOT present: TypeScript, Python, Java, C++, Go, Rust, SQL, PHP).*

---

### 2. Frontend

- **Frameworks**: 
  - **Production Extension**: **None** (Intentionally engineered as a zero-dependency native Web Extension).
  - **Testing/Validation**: **React 19** (`react@19.3.0`, `react-dom@19.3.0`, `react-dom/server`) used in `scratch/run_real_compilation_test.js` to validate generated JSX compilation.
- **Libraries**:
  - `scheduler@0.28.0` (Transitive dependency pulled by `react-dom`).
  - Otherwise **zero external runtime libraries**.
- **UI Frameworks**:
  - **Custom Design Token Engine**: `utils/theme.js` implements an internal design system via CSS custom properties (`--q-bg-primary`, `--q-accent`, etc.) supporting Dark, Light, and System modes with synchronized repaints.
  - **Tailwind CSS**: Present as a **Target Output Grammar**, not a runtime dependency. `utils/tailwind_mapper.js` is a custom compiler that maps computed CSS declarations into Tailwind utility classes.
- **State Management**:
  - **Custom Reactive Store / Pub-Sub (`ComponentState`)**: Implemented in `utils/component_state.js`. Acts as the single source of truth (SSOT), maintaining immutable original DOM snapshots alongside authoritative mutable current states (`current.html`, `current.css`) with event subscriptions (`change`, `theme`, `ai_edit`, `reset`).
- **Routing**:
  - **Tab-Based Navigation Controller**: Internal navigation engine inside `content/panel.js` managing 9 active tabs (`Live`, `Overview`, `Typography`, `Colors`, `Layout`, `Code`, `Edit`, `Assets`, `Settings`). No hash or URL history routing.
- **Forms**:
  - Native HTML Form Controls (sliders, textareas, provider selects, model dropdowns, theme toggles) handled programmatically via native DOM event delegation (`input`, `change`, `keydown`).
- **Validation**:
  - Client-side defensive parsing (`safeParseJson` in `utils/llm_service.js`), regex-based API key pattern detection (`detectProvider`), and HTML/CSS structure validation before iframe rendering.
- **Charts**:
  - **Visual Box Model Diagram Engine**: Custom DOM/CSS nested interactive visualizer in `content/panel.js` rendering live Margin, Border, Padding, and Content dimensions. No third-party charting libraries (no Chart.js, Recharts, or D3).
- **Editors**:
  - Multi-line instruction prompt editor with debouncing and submission hotkeys.
  - **Deterministic Regex Text Editor**: `utils/text_editor.js` performs zero-latency literal text node and attribute replacements without triggering LLM calls.
  - **Natural Language Style Mutation Parser**: `utils/style_editor.js` parses CSS commands ("make background blue") into structured declarations.
- **Utilities**:
  - **Shadow DOM API (`Element.attachShadow({ mode: 'open' })`)**: Complete CSS and DOM isolation preventing host-page style collisions.
  - **DOM Inspection APIs**: `document.elementFromPoint`, `window.getComputedStyle`, `Element.getBoundingClientRect`, Event Capture phase listeners (`addEventListener(..., true)`).
  - **Pointer Capture API**: `setPointerCapture` and `releasePointerCapture` for dragging the floating inspector panel.
  - **Clipboard API**: `navigator.clipboard.writeText` in `utils/clipboard.js`.
  - **Sandboxed Iframe Rendering**: Dynamic `srcdoc` compilation in `utils/preview_renderer.js` with canvas isolation.

### 3. Backend

- **Frameworks**: **None** (Architected as a client-side Chrome Extension).
- **Background Worker**: **Chrome Extension MV3 Service Worker** (`background/background.js`) managing tab lifecycle, keyboard shortcut dispatching, and dynamic content script injection.
- **Authentication**: Client-side API key management per provider stored in `chrome.storage.sync`.
- **Authorization**: None.
- **Validation**: Strict schema validation on inbound JSON responses from LLM endpoints.
- **ORM**: None.
- **File Upload**: None. Programmatic client-side export via `Blob` and `URL.createObjectURL` (`content/panel.js`).
- **Background Jobs**: Chrome Extension Event Alarms & Commands (`chrome.commands.onCommand`, `chrome.runtime.onInstalled`).
- **Logging**: Tagged structured client logging (`[DOMLens]`, `[DOMLens LLM]`, `[DOMLens Extractor]`) with console masking for secrets.
- **Middleware / IPC**: Chrome runtime messaging bus (`chrome.runtime.sendMessage`, `chrome.tabs.sendMessage`, `chrome.runtime.onMessage`) acting as an IPC layer between background worker, popup, and content scripts.
- **API Framework**: Native browser `Fetch` API with streaming `ReadableStream` consumption.

### 10. Security

- **JWT / bcrypt / OAuth**: None.
- **CORS**: Not restricted at runtime due to Chrome Extension Manifest V3 `host_permissions: ["<all_urls>"]`.
- **Rate Limiting & Concurrency Controls**:
  - Client-side concurrency lock (`isApplyingEdit`) preventing race conditions and double billing on duplicate clicks.
  - Client-side retry caps and exponential backoff on transient errors (503).
- **Helmet / CSRF**: None (No HTTP server).
- **Content Security Policy (CSP)**: Strictly compliant with Chrome Extension MV3 CSP (no `eval()`, no inline scripts, no remote script loading).
- **XSS & Injection Defenses**:
  - DOM isolation via Encapsulated Shadow DOM (`mode: 'open'`) preventing page scripts from reading extension UI or secrets.
  - Sandboxed `<iframe>` with `srcdoc` rendering for live preview of arbitrary third-party markup.
  - Web Component and Polymer template sanitization (`sanitizeHtmlForReact`) stripping unsanitized wrappers.
- **Secret Hygiene**: Zero hardcoded API keys. Keys stored only in browser storage; masked inputs in UI; console log sanitization ensuring API keys are never output to logs.

### 11. Architecture

- **Manifest V3 Multi-Tier Architecture**: Separation of concerns between Background Service Worker (lifecycle/commands), Content Scripts (DOM extraction and injection), Popup (extension entry point), and Encapsulated Shadow DOM (floating UI panel).
- **Encapsulated Shadow DOM Architecture**: Complete decoupling of extension UI from host page CSS cascade using Shadow Roots and custom CSS properties.
- **Single Source of Truth (SSOT)**: Unidirectional state pipeline where `ComponentState.current.html` and `current.css` dictate Live Preview, Code Generation, and AI edits.
- **Service Layer / Facade Pattern**: `utils/llm_service.js` abstracts multiple LLM vendors behind a uniform interface (`callLlmEditComponent`, `callLlmGenerateReact`), normalizing disparate error payloads, rate limits, and streaming formats.
- **Observer / Pub-Sub Pattern**: Centralized listener registry in `ComponentState` notifying components across state transitions.
- **Cascading Fallback & Circuit Breaker**: Graceful degradation pattern across 5 Gemini models when capacity issues (503) or decommissioned model IDs (404) occur.
- **AST / Code Transpilation Pipeline**: Multi-stage code generation pipeline in `utils/component_generator.js`:
  `Raw DOM` → `Sanitization` → `Nesting Resolution` → `HTML-to-JSX AST Mapping` → `Tailwind Class Injection` → `React JSX Output`.
